# ADR-081：用户资料同步的单台 OLT 保护、变更摘要与资料新鲜度

## 状态

已接受（2026-10-09）。

## 背景

- 网管二期全量同步逐台 OLT 读取后整表替换源快照。某台 OLT 在网管里匹配不到（IP 映射、设备名变化）时按 0 条处理，这台 OLT 的全部用户会从合并结果中消失，而整体只在“合计 0 条”时才拒绝。
- 合并只记录条数和冲突数，看不出本次与上次相比哪些用户新增、消失或换了坐标，异常不易发现。
- 一期 BOSS 增量向前重叠一天，重叠部分的工单每次都会重新逐条请求详情。
- 外勤主要在飞书查询，卡片看不出资料是什么时候同步的。

## 决策

1. **单台 OLT 保护**（`src/network-source-guard.mjs`）：网管二期读取改为逐台记录结果；某台 OLT 匹配不到、返回 0 条，或上次 ≥20 条且本次减少超过 30% 时，保留该 OLT 上次的源快照并返回告警，其它 OLT 照常更新。桌面端同步完成后弹窗列出告警，现场确认是真实变化时可带 `acceptDrops: true` 重新同步；定时任务始终按保护规则执行。
2. **变更摘要**（`src/merged-onu-change-summary.mjs`）：合并提交前与当前 `merged_onu_snapshots` 比较，按 LOID（无 LOID 时按坐标）统计新增、消失、换坐标、改名、联系方式变化，连同二期告警写入 `merged_onu_sync_runs.summary_json`（第 15 版迁移），在“用户资源管理”页展示。摘要只用于展示，读取旧快照失败不影响合并。
3. **BOSS 详情去重**：增量运行前读取重叠窗口起点之后已入库的工单幂等键，列表阶段命中的工单不再请求详情；这些工单本来就会被幂等提交忽略，结果不变。
4. **资料新鲜度**：飞书用户查询、ONU 详情、历史光功率和村级抢修卡片附“用户资料同步于 …”；超过 36 小时未成功同步或之后有失败记录时提示资料可能不是最新。

## 后果

- 二期快照可能暂时混有某台 OLT 的上次数据，告警会持续显示在“用户资源管理”页，直到下一次正常同步或现场确认接受。
- 只增加本地读写和少量判断，不增加对网管和 OLT 的请求；BOSS 详情请求减少。

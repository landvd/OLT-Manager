# ADR-077：企业微信智能机器人集成与多意图只读排障架构

## 状态

已实现，已现场验证（2026-09-14）

## 背景

现场装维工程师在日常宽带抢修与装移机过程中，普遍使用手机端企业微信进行沟通。此前系统仅支持飞书机器人查询，而在企业微信生态中，各局点网络环境多处于专用内网或 NAT 之后，不具备分配固定公网 IPv4 或开放反向 Webhook 端口的条件。

企业微信现已提供基于 WebSocket 的长连接（API 模式），允许客户端主动向腾讯云建立长连接接收推送事件并回复消息。需要将飞书现有的多维查单、历史光衰时序追溯、整口 PON 态势、一级地址反查、村级主干抢修熔接定界及 Pi 专家问答能力平滑移植至企业微信，同时解决移动端输入交互与一级地址/用户地址歧义消解问题。

## 决策

### 1. 长连接架构与安全凭据持久化

- **出站长连接**：采用原生 WebSocket（`openws.work.weixin.qq.com`）长连接订阅模式（`aibot_subscribe`），客户端主动出站建立安全连接，无需配置外部公网 IP 或防火墙映射。
- **安全隔离存储**：
  - Bot Secret 使用宿主系统级加密存储（macOS Keychain / Windows DPAPI），由 `safeStorage` 托管，运行时仅保留安全引用（`credentialReference`）；
  - 子系统启用状态和非敏感运行配置写入本地加密文件（`wecom-state.json`），采用 AES-256-GCM 算法加密，严禁明文落地；
  - 严禁向代码仓库或版本控制系统提交任何现场机器人的 Bot ID 与 Secret。

### 2. 核心数据网关契约复用

- 完全复用只读数据网关（`OltDataGateway`），接入既有只读接口：
  - `queryUsers` / `queryUsersByDeviceNumber`：多意图台账检索；
  - `readOnuStatus` / `readOnuDetail`：单户实时状态与光功率读取；
  - `readOnuHistory` / `readOnuHistoricalOptical`：近 7 天历史光衰时序提取；
  - `queryPons` / `readPonStatusesByIp`：一级地址反查与整口 PON 状态排查；
  - `queryVillagePons` / `sampleVillagePonOnlineUser`：村级全量 PON 抢修定界抽检。
- **网关标识约定**：明确 OLT 实例由 `oltId` 属性标识（支持 `o.oltId || o.id` 兼容归一化），确保检索范围正确下发至数据层。

### 3. 一级地址反查 PON 优先与歧义消解

在现场排障术语中，“一级地址”代表 PON 口在资源表中登记的光交箱/路巷覆盖区域（`pon_ports.address`），而“用户地址”代表住户装机门牌（`merged_onu_snapshots.installation_address`）。为避免输入一级地址时被误判为检索用户名单，确立以下调度优先级：

1. **显式前缀指令优先**：
   - 显式查人：`用户 [关键词]`（如 `用户 坑口`），强制走用户台账检索；
   - 显式查口：`pon [关键词]` 或 `一级地址 [关键词]`，强制走一级地址反查。
2. **自然地名输入优先反查 PON 口**：
   - 包含村/路/街/巷/小区/花园/公寓/广场/市场/学校/厂/栋/幢/座/号/光交箱/楼等特征的文本，优先调用 `gateway.queryPons`；
   - **单口唯一命中**：直接展示该 PON 端口的整口运行态势卡片（各 ONU 在线/离线/光衰隐患排序），免去二次点击；
   - **多口命中**：聚合去重后展示 PON 端口列表卡片，并在会话中注册快速选单，卡片底部附带“切换为查用户”提示；
3. **平滑回退查人**：
   - 仅当 `queryPons` 未命中任何 PON 端口时，自动回退至用户台账的地址模糊检索（`find_by_address`）。

### 4. 移动端轻量会话状态机（Session Context）

针对企业微信单聊无复杂卡片按钮回调的特点，在进程内为每个用户维护一个 15 分钟有效期的轻量会话上下文：

- **数字序号秒开选单**：
  - 用户收到多候选人或多 PON 列表后，直接回复数字（如 `1`、`2`），系统根据会话上下文直接展开对应详情或整口态势；
- **翻页支持**：回复 `下页`、`上页`、`第X页` 切换多候选人分页展示；
- **连续无参排障指令**：
  - 在查看某用户详情后，直接回复 `历史`：自动追溯该用户近 7 天光功率时序与稳定性报告；
  - 在查看某用户详情后，直接回复 `整口`：自动反查该用户所在 PON 端口全量态势；
  - 在查看某用户详情后，直接回复 `LOID`：单独提取纯文本 LOID，便于手机端长按复制。

### 5. 严格只读与大模型兜底分流

- **只读红线**：企微机器人的任何指令均只调用只读数据层，严禁下发任何配置写指令、Telnet 交互或重启设备命令；
- **大模型防穿透**：常规台账查单未命中时，输出结构化帮助和未匹配指引卡片，绝不将非排障问题直接丢给大模型导致输出“条件不足”等困惑回复；
- **专家排障分流**：仅当消息明确包含技术排障特征词（如 LOS、DyingGasp、掉电、断纤、流氓ONU、门限、配置教程等）时，才调用 `piAgentEngine.chat` 提供辅助排障参考。

## 不在本决策中的内容

- 不支持外部通过企业微信写入或修改 OLT 任何配置；
- 不在客户端中保存明文凭证；
- 不提供跨群/跨企业的数据穿透；
- 不依赖公网域名或反向代理穿透服务。

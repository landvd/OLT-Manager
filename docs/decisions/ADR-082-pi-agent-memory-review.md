# ADR-082：Pi Agent 记忆审核、飞书上下文与用户资料修正建议

## 状态

已接受（2026-10-10）。

## 背景

- 飞书调用 Pi Agent 时走官方 SDK 路径，该路径提前返回：召回的记忆不进入提示词，回答后也不做错误写法检查和学习，记忆系统在主要使用场景里没有生效。
- 飞书每次只传当前一条消息，“不对，应该是……”这类纠正看不到上一轮回答。
- 学到的内容立即成为“最高优先级、永久生效”的规约，没有审核、无法撤回；任何人说一句“记住：……”都会生效。
- 用户电话 / 地址的纠正按姓名记成记忆，重名时会张冠李戴，也不会回写到台账。

## 决策

1. **记忆分状态**（第 17 版迁移）：`agent_learned_memories` 增加 `status`（candidate / active / rejected）、`source`、`reviewed_at`。对话中自动学到的内容一律为候选；只有 active 会被召回。已生效的记忆被新对话改写内容时回到候选；已驳回的不会被自动重新激活。升级前已有的记忆保持 active，避免升级后行为突变。管理员手动添加的规约直接生效。
2. **SDK 路径补齐**：`chat()` 先召回已生效记忆，作为“管理员已审核的现场规约”传入 SDK 提示词；SDK 回答后与其它路径一样做错误写法检查并提取候选。
3. **飞书短期上下文**：同一会话同一人 30 分钟内最近 3 轮问答随新问题一起交给 Pi Agent，仅保存在进程内存，不落库。（SDK 路径已由 ADR-085 的永久对话取代；内存中的最近 3 轮仍用于“不对 / 没用”识别和记忆提取。）
4. **用户资料修正建议**：对话中的电话 / 地址纠正不再写成记忆，而是写入 `agent_user_corrections`：按姓名在合并台账查找，唯一匹配时带出 LOID 和原值，重名或查不到时由管理员在审核页确认 LOID。通过后立即更新 `merged_onu_snapshots` 对应用户，并在之后每次同步合并时由 `applyUserCorrections` 重新套用。
5. **桌面审核页**“Pi 知识审核”：知识与规约、用户资料修正两类，按待审核 / 已生效 / 已驳回筛选，支持通过、驳回、编辑、删除和手动新增规约。

## 安全边界

- 学习与审核只影响 Pi Agent 的回答提示和本地台账资料，不扩大命令白名单，不触发任何 OLT 写操作。
- 资料修正只改本地合并台账中的电话、装机地址两个字段，不回写网管二期或 NMSE。

## 后果

- 新学到的规约需要管理员定期在审核页处理；未审核的候选不影响回答。
- 删除已生效的资料修正后，下一次同步合并会恢复为源数据。

# ADR-090：一期 BOSS 查询镇区可配置与当天装机即查

## 状态

已接受（2026-10-13）。

## 背景

- 一期网管 BOSS 工单查询的“查询内容”固定写死为“厚街镇”（客户端请求参数、增量运行时、来源清单校验、数据库写入共 6 处）。部署到其它镇区时会查错范围，而且无法在界面修改。
- 合并台账以网管二期 ONU 列表为主，几天才全量同步一次。外勤装好新用户后当场要查资料和光功率，但新用户还不在台账里，查不到。
- 一期网管 BOSS 页面按“开始时间当天 0 点、结束时间此刻、处理状态成功、操作状态全部、查询内容为镇区”查询，能查到当天已完成的装机工单，工单里有 OLT IP、ONU 坐标、LOID、姓名、电话和地址。本机数据核对：近期 89 条装机 / 移机 / 换机工单中 88 条的坐标与之后同步进台账的坐标一致。

## 决策

1. **查询镇区可配置**（第 27 版迁移）：`resource_management_config.boss_query_content`。桌面“用户资源管理 → NMSE-PON 服务器配置”和配置向导新增“查询镇区”输入框（2–20 个汉字、字母或数字）。已配置过一期网管的旧数据迁移时填为“厚街镇”，行为不变；新部署未填写时，BOSS 增量同步和当天装机都拒绝执行并提示先填写。
   - 客户端 `getBossOperations` 的 `queryStr`、增量运行时的过滤和来源清单 `scope.content` 都使用配置值；清单校验只要求镇区为 2–20 个汉字、字母或数字，旧清单（厚街镇）仍然有效。
2. **当天装机**（`src/recent-install-sync.mjs`、`boss_recent_installs`）：
   - 按上面的 BOSS 页面查询方式读取当天 0 点到此刻的成功工单，只保存坐标和用户资料；同一 LOID 只保留最新一条，保留 7 天。已保存过的工单不再请求详情。
   - **不推进 BOSS 增量水位、不写一期源快照、不改合并台账**；与定期的“一期 BOSS 增量同步”互不影响。单条工单缺字段时跳过，不拒绝整批。
   - 查询时由 `getUsersWithRecentInstalls` 把当天工单叠加到合并台账上（飞书、Pi 和数据网关的所有查询）：工单接收时间晚于台账同步时间时以工单为准——新装的户加上，移机 / 换机的户换到工单坐标，同坐标的旧户去掉，销户的户去掉；台账同步之后以台账为准。叠加出来的户标记 `source: "boss-recent"`，飞书用户卡片的“资料时间”显示“一期网管工单：时间（新装或移机，台账还没同步到这户）”，工单保留 7 天，不一定是当天。实时状态和光功率仍按坐标用 SNMP 只读查询。
   - 触发方式（1.3.10 现场反馈“误报太多”后收紧）：只有按 LOID（8–24 位字母数字）或 11 位手机号查不到，或者话里明确说“新装 / 刚装 / 今天装 / 刚开通”等时，才回复“正在从一期网管同步今天的装机工单”并读取，读到新工单再查一次；按姓名、地址查不到和其它问话不再触发。两次读取至少间隔 2 分钟。
   - 飞书发“今天新装”“今日装机”“今天装了哪些”等，列出当天工单（时间、业务、姓名、地址、LOID、是否已进台账，不显示 OLT IP），外勤再按 LOID 查详情。机器人菜单可加“今天新装”，事件 ID 为 `recent-installs`，点菜单把同样的列表发到用户单聊。桌面“用户资源管理 → 今日装机”可手动同步并查看。

## 边界

- 只读一期网管（与增量同步相同的只读接口），只写本地 SQLite；不调用任何写接口，不触发设备命令。
- 地址清洗中针对“厚街镇”地址前缀的规则（例如合并台账的地址去前缀）不在本决策范围内，其它镇区部署时另行处理。

## 后果

- 部署到其它镇区只需在界面填写查询镇区。
- 外勤装机后在飞书即可查到新用户；桌面版“ONU 数据查询”等直接读台账的页面仍要等台账同步。

# ADR-087：用户归属字段（村 / 小组 / 小区）

## 状态

已接受（2026-10-11）。第一步：字段、计算、维护界面和显示；查询改为按字段过滤留到第二步。

## 背景

- 合并台账只有装机地址。每次按村、小组查询都要现场扫一遍全部地址，再叠加村名匹配、区域字典小组和“地名改归属”三套规则；飞书规则路径、弱光、断纤和 Pi 地名工具各自调用，结果可能不一致。
- 本机台账副本（14971 户）按地址自动识别：约 82% 能归到村；约 2700 户认不出村，主要是小区、工业区和道路（伦品涌工业区 249 户、万达广场 211 户等）；299 户地址为空。外勤口中的“厚街村榄树厦”在地址里写作“珊美榄树厦村”，每次查询都只能靠猜。

## 决策

1. **字段**：迁移 v22 在 `merged_onu_snapshots` 增加 `village`、`village_group`、`community`、`place_source`。字段是计算结果，台账同步重写整表后自动重算。
2. **计算顺序**（`src/onu-places.mjs`，纯函数）：
   - 村：单户修正 > 口归属 > 批量规则 > 区域字典已通过的“地名改归属” > 按地址自动识别。
   - 自动识别取最后一个“市 + X镇”之后的门牌部分，去掉“5桥头片”这类片区编码，取最早出现的已知村名；“X社区”等同“X村”。已知村名为地址中出现至少 20 次的“X村”，再并上区域字典登记的村。
   - 小组：单户修正 > 口归属 > 本村已通过的区域字典小组（候选不参与）。
   - 小区：单户修正 > 口归属 > 小区规则。小区与村相互独立，一户可以同时属于某村和某小区。
3. **批量规则**（`place_rules`）：类型为“归村”或“小区”，按地址关键词（包含 / 排除）匹配，最长关键词优先。用于把未归村的户成批归类。
4. **单户修正**（`onu_place_overrides`）：同时记录 LOID 和坐标。有 LOID 时按 LOID 匹配，坐标变了也照样生效；没有 LOID 时按坐标匹配。三项都清空即删除修正。
5. **重算时机**：读取合并台账（`getMergedOnuSnapshots`）和归属接口时比较指纹，有变化就整表重算，只写入变化的行（1.5 万户约 0.2 秒），未变化时只做一次比对。指纹包括：数据集版本、行数、已通过的资料修正（审核会直接改地址且不更新版本号）、已通过的区域字典条目、批量规则、单户修正。
6. **显示**：
   - “ONU 数据管理”（PON 台账）新增只读列“村 / 小组 / 小区”，由系统按口自动汇总、不需要填写，只列名称不显示户数（户数在不同镇区难以核对，容易被误当成要填写的数字），如“双岗村”“陈屋村、寮厦村”“陈屋村、未归村”，超过三项显示“等 N 处”；归属统一写成“村/小组”“村/小区”，如“厚街村/向北小组”“厚街村/万科城市广场小区”，没有村的小区写作“万达广场小区”；支持按归属筛选，导出 Excel 带这一列，导入时忽略。
   - “区域字典”新增“用户归属”标签页：总览、未归村地址建议（一键设为小区或归到村）、批量规则（含命中预览）、按村 / 小组 / 小区查看用户、单户修正。
   - 飞书用户详情卡片增加“所属村 / 小组 / 小区”；网关用户候选增加可选字段 `place`，并在网关契约中登记。
   - “ONU 数据查询”页不显示。
7. **按所在 PON 口推荐村**：没有村的户，看同一口（OLT IP + 板卡 + PON）上已归村的户最多属于哪个村，至少 3 户且占已归村户 60% 以上才推荐。推荐只做显示；内勤采纳（单户或批量）后写入单户修正，只填村，保留该户已有的小组、小区修正。本机台账副本 2719 户未归村中 1747 户有推荐，另有 225 户地址为空的也有推荐。
8. **口归属**（迁移 v23，`pon_place_assignments`，2026-10-11 依据现场反馈）：内勤觉得区域字典和批量规则太复杂，改为在“ONU 数据管理”里直接给某个 PON 口指定“村 / 小组 / 小区”。口上所有用户都归到这里（单户修正除外），来源记为 port；清空即恢复自动。键为 OLT IP + 板卡 + PON（不含框号），立即生效，与“保存台账”无关。手动指定的口在该列显示指定值并标“手动”。支持批量：在“操作”列勾选多个口（按口计算，同口多行勾任一行即可；按住 Shift 连续选择；可全选当前筛选结果），一次设成同一归属或一起恢复自动，服务端单个事务保存、只重算一次（`PUT /api/places/ports/batch`）。
9. **按台账行指定与分路**（迁移 v24，2026-10-11 依据现场反馈）：机房里加了分光器时，一个 PON 口会分成几路，分别供不同村 / 小区使用，每一路在 PON 台账里是一行（一级地址）。`pon_place_assignments` 改为以“口 + 一级地址”为主键，在“ONU 数据管理”里逐行勾选和设置，不再同口联动。用户层面没有“接在哪一路”的数据（网管只有坐标和地址），所以：
   - 一个口上已指定的各行归属都相同时，整口用户按它算；
   - 各行不同时，该口标为“分路”，不再整口套用，口上用户按各自地址自动判断，个别户用单户修正。
   迁移时，已有的按口指定展开到该口在台账里的每一行，效果不变；台账里没有该口时保留一条空地址记录。一级地址完全相同的重复行视为同一处。
10. **第二步：查询按归属字段**（2026-10-12，内勤整理完归属后，本机数据未归村 189 户）：数据网关新增地名解析 `resolvePlaceTarget`，把“厚街村”“厚街村下栅 / 下栅小组”“卓越维港 / 卓越维港小区 / 寮厦村卓越维港”解析为村、村 + 小组或小区，名称来自每户的归属字段和按行指定的归属。以下功能优先按字段过滤：
   - 村级抢修 PON 口（`queryVillagePons`）：命中户所在的口，加上按行指定为该目标、但台账里还没有用户的口（算主要口）。查小组或小区时返回已细分标记，飞书不再弹小组菜单。
   - 小组菜单（`villageRegionMenu`）：查村时列出该村下的小组和小区，按户数排序；飞书回传“村名 + 名称”能查回同一目标。
   - 弱光查询、断纤记录（`collectPlaceUsers`）、随机抽户比对（`sampleVillagePonOnlineUser`），以及 Pi 的地名工具（同一网关）。
   解析不到时（例如只说路名、没有设为小区的楼盘名），沿用原来的区域字典和地址匹配。区域字典里“小组的 PON 口勾选”不再影响按字段查询，改由“ONU 数据管理”按行指定。

## 边界

- 只读写本地 SQLite，不触发任何 OLT 命令，不回写网管二期或 NMSE。
- 第二步（第 10 条）之后，飞书、Pi 和抢修相关查询优先按归属字段；归属字段解析不到的说法仍按区域字典和地址匹配。

## 后果

- 内勤需要处理“未归村”清单，主要是在批量规则里登记小区和工业区。
- 区域字典里的小组要“已通过”才会写进用户的小组字段。

# ADR-088：资料包（Mac ↔ Windows 搬运内勤资料）

## 状态

已接受（2026-10-11）。

## 背景

- 内勤希望在 Mac 上补充资料（用户归属、区域字典、PON 台账等），再带回现场的 Windows。
- 现有组合备份是整库替换，而且飞书配置用本机系统钥匙串加密（Mac 用钥匙串、Windows 用 DPAPI），跨系统无法解密，跨系统还原时会清空目标机器的飞书配置。
- 如果把 Mac 整库还原到 Windows，Windows 的飞书机器人需要重新配置；从导出到导回这段时间里 Windows 新产生的数据（查询日志、学习建议、夜间光衰采样、抢修档案、Pi 记忆候选、同步记录）也会丢失。
- 如果把 Windows 整库还原到 Mac，备份里的定时同步任务和夜间采集设置会在 Mac 上继续运行，和 Windows 重复读取网管和 OLT。

## 决策

1. **Windows → Mac**：沿用组合备份整库还原。检测到备份来自其他操作系统时，还原后调用 `pauseScheduledWorkForCopy`：关闭夜间光功率采集；把等待中的定时同步任务标为失败，并写明原因。同时提示用户重启程序，改好的资料用资料包导回，不要整库还原回去。跨系统时飞书配置照旧被清空，所以 Mac 副本不会多出一个飞书机器人。
2. **Mac → Windows**：新增资料包 `olt-manager/data-package/v1`（JSON）。按类别导出整张表，每张表记录列名和按列顺序排列的行。共四类：
   - 用户归属：`pon_place_assignments`、`place_rules`、`onu_place_overrides`
   - 区域字典：`village_regions`
   - PON 台账：`pon_ports`
   - Pi 知识与资料修正：`agent_learned_memories`、`agent_user_corrections`
3. **导入**：
   - 先预览来源系统、版本、导出时间，以及每张表在资料包和本机的行数。
   - 用户勾选类别、明确确认后，先做一次数据库备份（原因 `data-package-import`），再在一个事务里整类替换所选表。
   - 只写入双方都有的列，资料包来自更新版本时缺少的列会被忽略。
   - 已通过的电话 / 地址修正立即写回合并台账，和审核通过时的效果一致。
   - 最后强制重算用户归属。
4. **其余数据一律不动**：飞书配置、查询日志、夜间采样、抢修档案、合并台账同步结果、OLT 配置。

## 后果

- 整类替换：Windows 上自上次导出以来对这几类资料的修改会被覆盖，包括外勤在飞书里新产生的 Pi 记忆候选。约定维护期间只在一台机器上改这几类资料。
- 单户修正按 LOID 或坐标对应。两台机器的合并台账来自同一网管，能对得上。
- 本机真实台账副本实测：用户归属 1000 条单户修正、PON 台账 983 行，资料包约 154 KB，导出 9 ms，导入 0.4 s。

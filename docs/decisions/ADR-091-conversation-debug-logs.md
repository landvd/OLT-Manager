# ADR-091：飞书与 Pi Agent 对话调试日志

## 状态

已接受（2026-10-13）。

## 背景

- 现场反馈“回答不对”“审批后没变化”时，只能靠截图猜。`feishu_query_logs` 只记提问、回复类型和结果数，不记机器人实际回了什么；Pi Agent 的工具调用过程只在 `pi-durable.sqlite` 里，桌面上看不到。
- 一次提问可能发出多条回复（例如先“正在同步”，再出结果卡片），按钮点击（翻页、提交表单、审批）也完全没有记录。

## 决策

1. 新表 `conversation_logs`（第 29 版迁移），每条记录一次处理：
   - `feishu`：每条飞书消息。记提问、别名改写、识别结果（意图、值、本地规则 / 已学说法 / 大模型）、查询类型和结果数，以及这次处理中发出的**全部回复**（按顺序，注明是否替换原卡片、是否发往其它会话，例如审批卡发给审批人）。
   - `feishu-callback`：每次按钮点击。记按钮动作、序号、页码和表单填写内容，以及发出的回复或拒绝原因。
   - `pi-feishu` / `pi-desktop`：Pi Agent 每轮问答。记问题、回答、来源和模型、错误原因（SDK 出错照常回退，原因也记下），以及**处理过程**：模型每一步的说明、调用的工具和参数、工具返回（截断到 4000 字）、工具用时、每步的 token 用量。
   - 飞书消息与它触发的 Pi 问答用同一个 `request_id`（`feishu:<事件 ID>`）关联，详情里一起显示。
2. 回复按原样记录（JSON），只去掉按钮令牌、过期时间等内部字段；人员姓名、电话、地址照常记录（本机日志，本地模型，与 ADR-085 的不脱敏决定一致），凭据不会出现在回复里。
3. 只存本机 SQLite，保留 30 天、最多 20000 条，写入时定期清理；写日志失败只打警告，不影响回答。
4. 桌面“飞书查询日志 → 对话调试”：按来源（飞书消息 / 飞书按钮 / Pi Agent）、时间范围和关键词（提问、回复、人员、错误）筛选；点开看完整详情，可“复制全部”发给开发排查。可勾选多条（表头可全选本页）一键导出：文本（.txt，与“复制全部”同格式，方便阅读和转发）或 JSON（.json，完整字段）；导出时自动带上所选飞书消息触发的 Pi 问答，按时间正序，一次最多 500 条。
5. 接口：`GET /api/conversation-logs?channel=&q=&openId=&days=&limit=&offset=`、`GET /api/conversation-logs/:id`、`POST /api/conversation-logs/export`（`{ ids }`）。

## 边界

- 只读写本地 SQLite；日志不发给大模型、不进入飞书回复，不纳入资料包。
- 组合备份 / 整库还原会带上这张表（与其它运行数据一样）。

## 后果

- 现场问题可以按时间和人员直接找到机器人当时的识别、回复和 Pi 的每一步。
- 每条记录多一次本地写入，对回复速度无感知影响。

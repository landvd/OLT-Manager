# ADR-080：夜间光功率基线、断纤前后逐户对比与区域字典

## 状态

已接受（2026-10-09）。

## 背景

现场最重要的场景是“整村断纤抢修后，确认熔接质量”。原有飞书“查某村抢修情况”对每个 PON 口只随机抽 1 个在线用户，拿它的当前收光与历史记录比较。问题：

- 抽样只代表一户，熔接点变差但抽到的恰好是好的用户时会漏判；
- 光功率历史只在有人查询时顺带记录，断纤前的数据经常为空；
- 断纤前就离线的用户会被当作“未恢复”，外勤白跑；
- 大村范围过大（例如厚街村地址命中 118 个 PON 口），其中不少口只有 1–2 户沾边，抢修时无法只查断纤所在的小组。

## 决策

1. **夜间光功率基线**（`src/optical-baseline-scheduler.mjs`、`onu_optical_nightly_samples`）
   - 每天固定整点（默认 2:00，可在系统设置修改或关闭）对已启用 OLT 逐台、逐个 PON 口调用既有 `listOnus(olt, pon)`，即 AGENTS.md 允许的 SNMP v2c 只读 walk，不新增 OID、不使用 Telnet。现有查询只支持按单个 PON 口读取（先编码 PON 索引再 walk），不带 PON 时返回空；PON 口清单取 PON 台账与合并台账坐标的并集，每台 OLT 同时最多读 2 个口。（1.2.24 测试包曾误用整机读取，导致全部 OLT 返回 0 个 ONU，1.2.25 修正。）
   - 只保存坐标、在线状态（online/offline/unknown）与在线时的收光 dBm；序列号、名称等不入表。同一晚重复采集覆盖写入，保留 30 天。
   - 桌面电脑夜间常关机：启动时若当天已过采集整点且没有成功记录，2 分钟后补采一次。单台 OLT 失败记为“部分成功”，不影响其它 OLT。
   - 网管二期补充（第 25 版迁移，2026-10-12）：网管二期 ONU 列表的收光值每天 0 点更新，与本采集测的是同一指标（本机副本对比 10847 户，平均相差 0.27 dB）。某台 OLT 的 SNMP 读取整台失败时，从二期 ONU 列表补该台当天的数据；部分 PON 口读取失败或有用户却没返回数据时，只补这些口。复用台账同步已在用的 ONU 列表只读读取（`readOnuInventory`），每台 OLT 只读一次，只取坐标、在线状态和收光，不调用“光功率刷新”等会触发设备采集的操作。采样记录来源 `source`（`snmp` / `oss-ngb`）；整台靠二期补上的 OLT 记为“部分成功”，运行记录写明补充户数或补充失败原因。断纤识别（抢修档案）只用 SNMP 数据，二期 0 点状态不参与。弱光查询卡片注明多少户用的是二期数据。
2. **断纤前后逐户对比**（`src/optical-baseline.mjs`）
   - 每个 PON 口找出最近一个“整口离线”夜晚（≥2 户且离线比例 ≥80%）视为断纤夜，基线取其之前最近 7 晚每户在线收光的中位数；没有断纤夜时取今天之前最近 7 晚。
   - 逐户分类：变化不超过 1 dB 为正常，变差 1–2 dB 轻度，变差 2 dB 以上需复核熔接；断纤前在线、现在离线为“未恢复”；断纤前各晚都离线为“断纤前已离线”，不计入未恢复。
   - 定界提示：可比较用户 ≥3 且 60% 以上变差 2 dB → 主干熔接点；2 户以上 → 分光器后分支段；1 户 → 入户段。
   - 没有夜间基线的 PON 口回退到抽样对比（1.2.29 起为按需多户抽测）：每口先测 1 户，没变差 2 dB 即结束，超过时加测到最多 5 户；“之前”取 24 小时以前历史记录的中位数。多数（≥60%）抽测用户变差 2 dB 以上判为光路 / 熔接问题，少数变差判为用户侧原因，只有 1 户可对比判为样本不足。
3. **区域字典**（`src/village-regions.mjs`、`village_regions`）
   - 村 → 小组 → 地址关键词（包含任一即属于、命中排除词则不属于）。候选由合并台账地址自动发现：取地址中最后一次出现村名之后的地名前缀，户数 ≥5 的两字前缀按 90% 一致度向后延伸，去掉道路后缀和门牌序号。
   - 状态分为待审核 / 已通过 / 已驳回，由管理员在桌面端“区域字典”页审核；重新识别不覆盖已审核或已驳回条目。
   - 飞书查询主要 PON 口超过 15 个且未指定小组时，先回复小组菜单（已通过的蓝色在前，自动识别待审核的灰色）；首次遇到的大村自动生成候选。
   - 每个 PON 口按“命中户数 ≤2 且占该口户数 <30%”判定为零星相关口，默认不纳入抢修检查，卡片提供“检查零星相关口”按钮。
   - 小组的 PON 口（第 16 版迁移，1.2.26 起）按三条依据确定：PON 台账一级分光地址命中小组关键词（去掉“镇/村”前缀后的地名，如“菊塘”“向北”）且该口确有本村用户（避免别村同名道路误命中）；小组用户在该口不是零星沾边；管理员在“区域字典 → PON 口”中手动勾选或剔除的口优先（`pon_include_json` / `pon_exclude_json`，只保存与自动判断不同的部分）。分光点比用户地址更接近光缆物理走向，审核一次后小组范围固定。
   - 飞书抢修卡片（1.2.26 起）改为：标题颜色即结论、一句话结论、四个关键数字，名单每类预览 5 户；“完整名单”“按 PON 口查看”在同一张卡片内切换，不再刷出新消息。
   - 地名改归属（第 20 版迁移，1.3.1 起）：小组可勾选“整村查询时归入本村”（`transfer`），用于地址写的是别村、实际归属本村的地名（如商业广场）。只有已通过的小组生效：查本村整村时带上命中该小组关键词的用户，查地址里那个村时排除这些用户；原村自动识别小组时不再生成该地名，小组 PON 口判断时这些用户算作本村用户。

## 安全边界

- 夜间采集只调用既有 SNMP 只读查询；SNMP 失败时的补充只读取网管二期 ONU 列表；区域字典和基线只读写本地 SQLite。
- 不改变命令白名单，不向 OLT 写入任何配置。
- 抢修卡片中的姓名、地址、电话来自本地合并台账，与现有用户详情卡片的展示范围一致。

## 后果

- 抢修结论从“每口一户抽样”变为“全口逐户对比”，并能直接列出需要复核熔接和未恢复的用户。
- 新装后需要积累几晚数据（建议 ≥3 晚）对比才可靠；在此之前按原抽样逻辑工作。
- 每天多一轮逐口 SNMP 只读 walk（现场约 750 个 PON 口），对每个口的压力与在“ONU 数据查询”里查看一次该口相当。

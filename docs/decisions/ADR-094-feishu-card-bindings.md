# ADR-094：飞书卡片按钮令牌落库

## 状态

已采纳（1.3.32）。

## 背景

飞书卡片上的每个按钮带一个随机令牌，令牌对应的内容（哪份预算、哪一行、哪些候选用户、表单要填什么）原来只存在程序内存里：用户查询卡片 5 分钟、定额卡片 30 分钟后作废，程序一重启（自动更新、电脑重启）就全部丢失。现场早上做的定额晚上要改，点旧卡片就提示过期。

## 决定

1. **有效期**：定额卡片 3 天，用户查询卡片（候选列表、ONU 详情上的主地址光功率 / 复制 LOID / 历史、PON 和村级查询、资料修改表单）1 天。由用户决定。
2. **落库**：新增 `feishu_card_bindings` 表（第 33 版迁移），按令牌存卡片发出时记下的内容（JSON）、范围（`quota` / `query`）和到期时间。
3. **读写方式**：内存里照常用 Map（最多 1000 条，超出只挤出内存）；发卡片时同时写库；点按钮时内存里没有就从库里读回来；每次按钮处理完把“已使用”“已完成”等变化写回库；村级汇总在后台完成时也写回。“处理中”标记只在本次运行有效，读回时清空。
4. **清理**：每写 50 次删除一次过期记录。
5. **安全不变**：仍校验令牌、会话、发起人和有效期；定额按行号改删，行已删除只提示不会删错；用过的候选重启后仍记得，不会重复处理。

## 影响

- 卡片内容包含候选用户的姓名、地址等，和本机 SQLite 里已有的资料同级，只存本机。
- 定额模式“直接说话”的会话仍是 30 分钟；点 3 天内的旧卡片会重新打开会话。
- 查询结果最长可能是 1 天前的快照；点详情、光功率等按钮时仍实时读取设备。

# ADR-076：飞书断纤抢修五天连续监控模型

## 状态

已规划，待实现（2026-09-10）

## 背景

现有飞书村级查询会逐页聚合 PON，并为每个 PON 临时抽取在线 ONU，对比当前与历史 RX 光功率。它适合一次性抢修复核，但没有持久化故障事件、固定样本、连续五天观察或可恢复调度，因此不能据此宣称线路已经稳定恢复。

这里的“一级地址”是一级 ONU 的安装/覆盖点，不是行政镇。村级归属必须从用户装机地址提取，再反查 ONU、一级地址、PON 和光路；原始地址与归属置信度均须保留。

## 决策

后续实现必须把一次断纤抢修建模为独立的本地 SQLite 事件，不能只保存在飞书卡片或进程内状态。首版建议使用四组实体：

- `fiber_recovery_incidents`：事件 ID、发现/抢修完成时间、来源摘要、观察状态、五日窗口和最后采集时间。
- `fiber_recovery_scopes`：事件影响的村级归属、一级地址、OLT/PON 范围、归属方法、置信状态和异常原因。
- `fiber_recovery_samples`：每个一级地址或线路分层的主样本、备用样本、选择理由、有效期和替补关系。
- `fiber_recovery_observations`：采样时间、只读在线状态、RX 光功率、历史来源、采集结果和脱敏错误分类。

事件创建、范围快照和样本选择属于本地数据写入，不触发 OLT 操作。设备侧仍只允许既有 SNMP v2c `get/walk`、固定 show 查询及网管二期历史光功率只读接口。

五天观察按 `Asia/Shanghai` 连续自然日计算。每个采样分层每天至少要有一个有效观测；建议一天三个固定窗口，但实际时刻必须可配置。主样本失败时可使用已登记备用样本，并在结果中标注替补。任一分层缺日、缺少抢修前稳定基线、样本覆盖不足或来源不可用时，结论必须是“数据不足”，不能标记“稳定恢复”。

结果状态至少区分：`observing`（观察中）、`stable`（满足五日门槛且趋势稳定）、`warning`（相对基线变差、波动或反复掉线）、`unrecovered`（仍未恢复）和 `insufficient_data`（数据不足）。具体 dBm 阈值不能在没有设备型号与现场历史分布证据时写死；判定应组合相对基线、设备/线路绝对阈值、持续时间和多样本一致性。

调度器必须持久化下一次采样时间、最近结果和失败分类；进程重启后只恢复未完成的只读采样，不重复创建事件。会话失效允许一次自动重新登录并重试；仍失败时保留旧观测、显示明确告警并等待下一窗口，不把失败当作正常。

飞书只展示聚合、异常与人工复核优先级，默认不列出完整用户明细。单个样本正常只代表该样本覆盖分层，不能代表整个一级地址或村级光路正常。

## 留存策略

首个实现阶段不自动删除事件或观测。完成真实五日运行验收后，再复用现有“先 dry-run、后显式确认”的备份清理边界增加可配置留存：建议事件汇总与每日聚合长期保留，原始观测默认保留 180 天，允许在 30–365 天范围调整。任何清理前必须完成数据库备份并列出精确候选；活动事件、数据不足事件和人工标记保护的事件不得清理。

## 分阶段验收

1. 先以脱敏 fixture 验证村级归属、主/备抽样、五日连续性、缺日和基线不足。
2. 再实现本地事件/观察查询与重启恢复，不接入自动告警来源。
3. 接入飞书聚合卡片，核对卡片数量与本地查询一致。
4. 最后进行连续五个上海自然日的现场只读验收；此前只能称为“功能/调度验证”，不能称为“五天稳定恢复已验收”。

## 不在本决策中的内容

- 不自动发现、修复或关闭上游断纤告警。
- 不执行 ONU 注册、删除、重启、配置或保存命令。
- 不在缺少基线时使用单一固定 dBm 阈值。
- 本 ADR 不代表五天监控功能已经实现。

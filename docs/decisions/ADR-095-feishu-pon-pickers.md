# ADR-095：飞书“查 PON 口”“抢修验收”改用下拉框选择卡片

## 状态

已采纳（1.3.34）。

## 背景

现场在手机飞书上查整村 PON 口和抢修验收，要打“XX村所有PON口”或“XX村抢修情况”。两句话只差几个字，容易打错或输错村名。另外，原来这两句话走的都是同一个抢修验收流程，结果卡片一样，“查 PON 口”实际上没有单独的功能。

## 决定

1. **两个菜单，两张卡片**：菜单事件 `pon-list`（查 PON 口，蓝色）和 `pon-repair`（抢修验收，橙色）把选择卡片发到用户单聊。卡片用 JSON 2.0 表单，用下拉框（`select_static`）选村，不用输入框，所以不会输错格式。
2. **村名来源**：新增只读网关方法 `listVillages`，按合并台账的村归属统计每个村的户数（户数多的在前），再补上 PON 台账行指定的村和区域字典里已通过的村。下拉框最多列 100 个村，超出时提示直接发文字查询。
3. **选村后再选范围**：飞书表单里的两个下拉框不能联动，所以选村后卡片原地换成第 2 步，用“范围”下拉框选“整村”（默认）或某个小组 / 小区（楼盘）（来自 `villageRegionMenu`）；没有小组的村直接出结果。查 PON 口（1.3.35 起）和抢修验收都分这两步；整村抢修验收不再弹小组菜单。
4. **查 PON 口 = PON 口清单**：每页列 10 个口（大村 100 多个口时少翻几页），显示 OLT、坐标、一级地址、本村户数和口上户数，零星沾边口加标记；点“整口状态”实时读取该口（`readPonStatuses`），可以重复查看；可以翻页（原卡片替换）。清单只读台账，不读设备，所以几乎立刻就有结果。
5. **最近查过**：按人和功能分开记最近 4 次（抢修验收会记下小组），存在 `feishu_card_bindings` 表里（范围 `query`，令牌 `pon-recent|模式|open_id`），保存 90 天。选择卡片本身 1 天有效，程序重启后也能用。
6. **再查一个村**：PON 口清单和从选择卡片发起的抢修验收结果卡片（概览页）都有“再查一个村”按钮，点了重新发一张同一功能的选择卡片。
7. **文字查询分开**：“XX村所有PON口”“XX村pon”“XX村的光口”出 PON 口清单；“XX村抢修情况”等出抢修验收；大模型识别为 `find_pons_by_village` 时出 PON 口清单。只发了台账里有的村名（如“厚街村”）时，回一张“查 PON 口 / 抢修验收”二选一卡片。
8. **校验**：选择卡片的回调来自单聊的 open_chat_id，和菜单发卡时的 open_id 不同，所以按发起人（或同一会话）校验；下拉框提交的村名必须在发卡时列出的村里；仍校验令牌、有效期和 OLT 启用情况。

## 影响

- 只读：不改动设备，不新增写操作；新增的网关方法只读本机台账。
- 管理员需要在飞书开放平台的机器人菜单里加两个菜单项，事件 ID 分别为 `pon-list` 和 `pon-repair`。
- 以前发“XX村所有PON口”出的是抢修验收结果，现在出 PON 口清单；要做抢修验收请发“XX村抢修情况”或用菜单。
- 只发村名以前会按地址查用户，现在会先让人在两个功能里选一个。

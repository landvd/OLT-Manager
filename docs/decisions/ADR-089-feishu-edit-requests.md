# ADR-089：飞书资料修改申请与审批

## 状态

已接受（2026-10-13）。

## 背景

- 外勤在现场发现资料不对，例如 PON 台账一级地址写的是“君汇”，实际是“顺景大厦”；或者某户的村 / 小组 / 小区归错了。以前只能口头告诉内勤，再由内勤在桌面版修改。
- 已有的“用户资料修正”（ADR-082）只覆盖电话、装机地址，而且要到桌面版审核页处理。

## 决策

1. **开放范围**（依据用户决定）：只开放两项——PON 台账的一级地址、某户的村 / 小组 / 小区归属。姓名、LOID、电话等不在此流程内。
2. **审批人**：一人，由内勤在桌面版“飞书查询日志 → 资料修改”中从和机器人说过话的人里选择（飞书 open_id 按应用区分，无法直接填手机号）。没有指定审批人时外勤不能提交。
3. **外勤提交**：
   - 用户详情卡片新增“资料有误”按钮，点开是一张飞书表单，默认填当前的一级地址和归属；口在台账里有几行（分路）时先选要改的那一行。只提交改动过的项，每项生成一条申请。表单 30 分钟内有效，只能提交一次。
   - 直接说“君汇那个口的一级地址应该是顺景大厦”“君汇的一级地址改为顺景大厦”：按一级地址关键词在 PON 台账里找行，发同样的确认表单（多行时选择），外勤确认后才提交。
   - 归属写法：“厚街村/下栅小组”“厚街村下栅小组”“下栅小组”（唯一时）“丰泰小区”“寮厦村卓越维港小区”“厚街村”；按已有的村、小组、小区名称拆分，新小组写成“村名 + 小组名”也能拆开。村后面没写“小组 / 小区”的部分（如“新塘村/顺景大厦”）：本村已有的小组按小组，已有的小区或楼盘名（大厦、花园、广场、苑、城等）按小区，认不出时提示外勤写清楚，不会丢弃（1.3.11 现场反馈后修订）。
4. **审批**：申请以卡片单独发到审批人飞书，卡片上有输入框，默认是外勤填的内容；审批人可先改正再点“同意”，或点“驳回”。审批令牌保存在 SQLite（`feishu_edit_requests`），可以隔天处理；只认指定审批人的点击，其他人点击会被拒绝；处理过的申请再点无效。结果通知到外勤提交时所在的会话。
5. **修改内容**：
   - 一级地址：把该口台账里一级地址等于原值的行改为新值；该行按行指定的归属（`pon_place_assignments`，键含一级地址，ADR-087 第 9 条）跟着搬到新地址，然后重算归属；写 `admin_events`。原值已不存在（已被他人改过）时不修改，提示审批人到桌面版核对。
   - 归属（1.3.10 现场反馈后修订，第 28 版迁移 `row_address`）：口在 PON 台账里时，改的是该户所在台账行（口 + 一级地址，分路时为外勤所选的行）按行指定的归属（`pon_place_assignments`），整行用户都按它算，与内勤在“ONU 数据管理”里维护归属的方式一致；表单默认填该行已指定的归属，没有指定时填这户现在的归属。口不在台账里时才写该户的单户修正（`onu_place_overrides`）。同意时原值与申请时不同，先更新原值并提示审批人确认，再次同意才修改。
   - 同一张表单同时改了一级地址和归属时，一级地址先同意改名后，待审批的归属申请跟着改到新地址。
   - 1.3.10 测试包里归属申请写的是单户修正，所以审批后“ONU 数据管理”看不到变化；该包产生的单户修正保留不动，需要时可在“区域字典 → 用户归属 → 单户修正”删除。
6. **卡片格式**（1.3.12 现场反馈后修订）：资料有误表单、修改确认表单、审批卡，以及提交 / 审批后替换它们的结果卡和通知卡，使用飞书卡片 JSON 2.0（`schema: "2.0"`，`body.elements`，表单按钮用 `form_action_type: "submit"` + `behaviors` 回调）。现场同一部手机上 JSON 1.0 卡片的表单整块不显示（17:57 能填、18:12 不显示，卡片内容相同）；飞书也不允许把 JSON 2.0 卡片更新成 JSON 1.0，所以结果卡一并改为 2.0。回调格式不变（`action.value`、`action.form_value`）。
7. **记录**：桌面版“飞书查询日志 → 资料修改”列出全部申请（申请人、对象、原值 → 新值、外勤原填、审批人、状态）。

## 边界

- 只读写本地 SQLite（PON 台账、归属修正、申请记录），不触发任何 OLT 命令，不回写网管二期或一期 BOSS。
- 审批卡片不显示 OLT 管理 IP。
- 桌面版“ONU 数据管理”页面若有未保存的台账编辑，之后点“保存台账”会整表覆盖，可能覆盖刚审批的一级地址；内勤保存前应先刷新。

## 后果

- 外勤发现的资料问题可以当场提交，审批人在手机上即可处理，资料修正不再依赖内勤转述。
- 新增第 26 版迁移：`feishu_edit_requests`、`feishu_edit_settings`。

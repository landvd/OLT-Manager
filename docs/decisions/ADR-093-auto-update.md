# ADR-093：启动时从双岗服务器自动更新

## 状态

已采纳。替代 `docs/design/update.md` 原先“取消启动自动更新、只保留手动增量包”的决定；手动增量包仍保留作为备用。

## 背景

现场只有一台 Windows 客户端，手动带增量包不方便。当年取消自动更新，是因为依赖旁路由的登录状态；现在更新目录是无需登录的 HTTP，现场客户端通过公网域名访问。

## 决定

1. **服务器**：只放静态文件：`channel.json`（签名的版本清单）和增量包 ZIP。地址写在客户端本地 `update-settings.json`，留空即关闭，所以 Mac 版不填就不自动更新；仓库是公开的，地址不写进代码。
2. **检查时机**：每次启动，在本地服务、飞书机器人和夜间采集启动之前，最多等 3 秒。没有新版本、连不上、验签或下载失败，都继续用当前版本启动。
3. **签名**：`channel.json` 用 Ed25519 签名，里面带 ZIP 的大小和 SHA-256；ZIP 内每个文件再按原有清单校验。私钥只在发布用的 Mac（`~/.config/olt-manager/update-signing-key.pem`），公钥在 `electron/update-public-key.cjs`。私钥丢失后要换公钥，并手动给客户端装一次。
4. **重启与回滚**：更新进程替换文件后拉起新版本并等待；新版本主窗口加载成功后写确认文件。120 秒内没写或进程退出，就恢复旧文件、记下 `skipVersion`、拉起旧版本，这个版本不再重试，等更高版本。
5. **发布**：`scripts/publish-update.mjs` 先传 ZIP，最后原子替换 `channel.json`；拒绝测试包，拒绝版本或校验值不一致的包。只有正式版才发布。
6. **不回退版本**：只有服务器版本高于本机才更新。发错了就发一个更高的版本。本机版本不在包的基线内时不更新，要整体包。

## 影响与限制

- 更新目录对公网开放且是明文 HTTP：任何人都能下载增量包，所以包里不能有现场数据或凭据；防篡改靠签名，不靠网络隔离。
- 回滚只恢复程序文件。新版本若已执行数据库迁移，回滚后旧程序面对的是新结构，所以带迁移的版本发布前要照常用真实数据副本验证。
- 程序常年不重启就不会更新。
- 更新代码本身有缺陷时自动更新可能失效，只能手动装增量包修复。

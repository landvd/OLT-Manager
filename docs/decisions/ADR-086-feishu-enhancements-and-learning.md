# ADR-086：飞书复测、弱光与断纤记录、群聊、查询日志与自我学习

## 状态

已接受（2026-10-10）。

## 背景

外勤主要在户外用飞书工作，最重要的场景是“整村断纤后恢复查光功率”。现有问题：

- 重新熔接后，必须再查一遍整村才能确认。
- 夜间光功率基线已有每户每晚的数据，但飞书查不了弱光。
- 抢修档案记了断纤，但外勤问不到某地的断纤历史。
- 只支持单聊，抢修常在群里协作。
- 没有提问记录，不知道谁问了什么、哪些问不出来。
- 自我学习只有 Pi Agent 记忆和未解决问题两条通道。

## 决策

1. **复测**
   - 抢修验收卡片上有异常、整口离线或对比未完成的口时，显示“复测这 N 个口”。
   - 复测只重读这些口，沿用原有逐户对比和抽测逻辑，不再分页查询整村；结果卡片标为“复测结果”，验收存档时注明“（复测）”。
   - 用户侧个别变差的口不进入复测。
2. **弱光查询**（`queryWeakLight`）
   - 按地名找用户：区域字典小组、村名（含地名改归属）、地址片段，依次尝试。
   - 只读最近一晚的夜间采样，不访问设备；接收光功率 ≤ −27 dBm 算弱光，与抽测“实时光功率合格”的门限一致。
   - 返回名单（最差在前）和弱光最集中的口。
   - 地名查不到时不作答，交给普通查询；“张三光衰”仍按人查。
3. **断纤记录**（`queryOutageHistory`）
   - 用同样的地名定位找用户，排除零星沾边的口，只看主要口在抢修档案里近 90 天的记录。
   - 按事件归并，列出最近的断纤和经常断的口。
4. **群聊**
   - 机器人被拉进哪个群，哪个群就能用；群里 @机器人 才回复，没有 @ 的群消息不回复，也不记日志。
   - 可用范围由飞书后台的应用可用范围控制。
   - 卡片按钮由群里任何人点击都有效（候选仍绑定会话）。
5. **查询日志**（第 21 版迁移：`feishu_query_logs`、`feishu_user_names`）
   - 每条提问记录这些内容：
     - 时间、人员（飞书姓名，读不到时可在桌面端填备注名）；
     - 会话（单聊，或群名）；
     - 原文和按别名改写后的文本；
     - 回复类型、结果（查到 / 没查到 / 帮助 / 出错）、识别方式（本地规则 / 大模型 / 已学说法）、用时。
   - 外勤回复“不对 / 没用”时，把上一条标为负面反馈。
   - 日志保留 180 天。
   - 桌面端“飞书查询日志”页有三个分页：日志、改进清单（各类统计、需要改进的说法、外勤使用情况、各类查询用时）、学习建议。
6. **自我学习**（`feishu_learning_suggestions`，都要管理员审核后才生效）
   - **村名别名**：同一人 5 分钟内先问 A 没查到、再问 B 查到了（限地名类查询），取两句不同的部分，各带一个相同的字作为别名候选。生效后在任何规则匹配之前，把提问里的 A 改写成 B。
   - **常用说法**：大模型识别成功的提问，把查询值换成 `{value}` 得到说法模板，累计出现次数。生效后在调用大模型之前先按模板识别，来源标为“已学说法”。
   - **答案草稿**：未解决问题的补答弹窗里可以让 Pi Agent 先起草，管理员修改后保存；不会自动生效。
7. **机器人菜单**
   - 订阅 `application.bot.menu_v6`。菜单 key 为 `help`、`help-repair`、`help-user`、`help-feedback`，分别对应帮助的各个主题。另有 `recent-installs`（今天新装，ADR-090），发当天装机工单列表。
   - 菜单事件没有会话 ID，回复按 open_id 发到单聊；不使用候选绑定。
8. 新增的飞书网关方法 `queryWeakLight`、`queryOutageHistory` 已登记在进程内网关白名单，并有经适配层的端到端测试。

## 安全边界

- 弱光与断纤记录只读本地 SQLite；复测沿用既有的 SNMP 只读查询；没有新增设备命令。
- 姓名和群名通过飞书开放平台的只读接口读取，需要应用开通相应只读权限；没有权限时留空，不影响查询。
- 日志只保存在本机 SQLite，不对外发送。

## 后果

- 需要在飞书开发者后台做以下配置：
  - 开通“接收群聊中 @机器人消息”；
  - 开通读取用户基本信息、读取群信息的权限；
  - 订阅机器人菜单事件，并配置菜单项。
- 别名和说法都是候选，需要管理员定期在“学习建议”里审核；审核后最多 1 分钟内生效（缓存），在桌面端审核时立即生效。

## 2. 术语和数据关系

这里的“一级地址”不是行政区划中的镇，而是一级 ONU 的安装位置或覆盖地址。

用户地址和一级地址的含义不同：

```text
一级 ONU
 ├─ 一级地址：一级 ONU 安装地 / 覆盖点
 └─ 下挂用户 ONU
     └─ 用户地址：具体用户安装地址
         └─ 村级归属：从用户地址中提取并标准化
```

因此：

- 一级地址用于定位设备、资源点和故障承载位置。
- 用户地址用于判断用户实际属于哪个村。
- 村级查询主要依据用户地址提取结果，不能把一级地址直接当成所有用户的村级地址。
- 故障定位仍需回到一级 ONU、OLT、PON 口和拓扑关系。

示例：某一级 ONU 安装在村口，但其下挂用户可能分布在多个村。查询“双岗村”时，应统计用户地址归属于“双岗村”的 ONU，再反向汇总这些 ONU 所属的一级 ONU、PON 口和光路。

## 3. 村级归属标准

用户地址可作为村级数据的主要来源。提取结果不能覆盖原始地址，至少应保留：

- 原始用户地址。
- 提取出的村级名称。
- 与上级地址组合后的标准归属。
- 提取方式：自动提取、人工确认或外部导入。
- 归属状态或置信度。
- 异常原因，例如缺少村名、同名村、地址格式异常或无法确认。

村级标准化需要处理：

- “村”“社区”“行政村”等名称差异。
- 村名后的组、队、自然村和门牌号。
- 同名村的上级区域区分。
- 简称、错别字和历史地址。
- 一个一级地址下存在多个村的情况。

查询结果必须区分“已确认归属”“推定归属”和“未归属”，不能把地址解析结果默认为现场百分之百准确。

## 4. 大范围断纤事件模型

事件来源可以是现有告警系统中的“大范围断纤”指示。进入系统后形成只读事件快照，至少包含：

- 事件发现时间。
- 来源系统和原始告警摘要。
- 影响的 OLT、一级 ONU、PON 口或其他可识别资源。
- 影响的 ONU 数量和用户数量（如果数据可得）。
- 当前事件状态：待确认、处理中、部分恢复、已恢复、数据不足。
- 最近一次采集时间。
- 恢复判定说明。

不能仅凭 HTTP 200、单次采集成功或单个 ONU 短暂上线判断事件已经恢复。

## 5. ONU 恢复判定

建议将恢复判定分为三个层次：

### 5.1 设备状态

- ONU 是否重新上线。
- PON 口是否恢复正常。
- OLT 是否仍存在相关告警。

### 5.2 稳定性

- ONU 是否连续多个采样周期在线。
- 五天内是否反复掉线。
- 光功率是否出现持续下降或明显波动。

### 5.3 事件汇总

一个一级地址或村级范围只有在主要抽样对象达到稳定条件后，才能标记为“稳定恢复”。否则应显示为“已上线但仍需观察”或“恢复不稳定”。

建议状态：

- 绿色：已恢复，光功率稳定。
- 黄色：已恢复，但相对基线明显变差或存在波动。
- 红色：仍未恢复、反复掉线或光功率持续恶化。
- 灰色：数据不足、采集失败或无法建立有效基线。

## 6. 抽样标准

初步方案是每个一级地址抽取一个 ONU 观察五天，但生产设计不应依赖完全随机的单点样本。

推荐最低方案：

- 每个一级地址设置一个主抽样 ONU。
- 同时保存一个备用抽样 ONU，主 ONU 无数据时替补。
- 优先选择近期长期在线、历史光功率完整、不频繁掉线的 ONU。
- 尽量选择具有代表性的线路位置。

更可靠的增强方案：

- 一级地址下存在多个 PON 口时，按 PON 口分层抽样。
- 存在不同分光方向、分支或资源点时，按线路分支抽样。
- 重要或历史故障地址可抽取 2～3 个 ONU。

抽样记录应可追溯，至少包含：

- 一级地址标识。
- ONU 标识和 PON 坐标。
- 抽样原因或规则。
- 采样起始时间。
- 备用对象。
- 当前是否仍为有效样本。

抽样结果只能代表样本覆盖范围，不能直接等同于该一级地址下所有线路的绝对质量。

## 7. 五天光功率复核标准

建议建立抢修前基线，再观察抢修后连续五天：

```text
抢修前稳定历史窗口
        ↓
抢修完成或恢复时间点
        ↓
恢复后连续五天采样
```

基线至少应记录：

- 抢修前的时间窗口。
- 平均值、最小值、最大值和有效采样数量。
- 上行和下行光功率（实际支持哪个方向取决于数据源）。
- 基线是否足够，是否受到历史掉线或采集缺失影响。

抢修后应比较：

- 当前值与抢修前平均值的差异。
- 五天内变化趋势。
- 突发波动和异常峰值。
- 采样缺失和掉线次数。
- 多个抽样 ONU 是否出现共同变化。

示例：

```text
一级地址：某一级 ONU 覆盖点
抢修前平均接收光功率：-21.8 dBm
抢修后第一天：-23.1 dBm
抢修后第五天：-24.0 dBm
结论：持续变差，建议复核熔接点、接续盒和相关分支
```

具体 dBm 阈值不能在没有现场设备型号、光模块标准和历史分布前直接写死。阈值应采用“相对基线变化 + 绝对安全阈值 + 持续时间”组合，并允许按设备或线路类型配置。

## 8. 飞书卡片展示内容

卡片应优先展示聚合结果，不默认列出全部用户：

```text
大范围断纤抢修复核

涉及一级地址：18 个
已恢复：16 个
仍异常：2 个
光功率变差：5 个
五天内反复掉线：3 个

重点复核：
- 双岗村相关一级地址：光功率较基线持续下降
- 某光交箱：ONU 已上线，但五天内多次掉线
```

建议支持的查询：

- 查询某次大范围断纤中已恢复和未恢复的一级地址。
- 查询某村仍未恢复的 ONU 或一级地址。
- 查询抢修后光功率较基线变差的对象。
- 查询五天内反复掉线的对象。
- 查看某一级地址的抽样 ONU、基线和趋势明细。

结果必须标记数据时间、最后采集时间和“数据不足”情况。

## 9. 安全和只读边界

本方案继续遵守 OLT Manager 的只读边界：

- 只允许读取告警、ONU 状态、PON 状态和历史光功率。
- 不执行 `snmpset`、ONU 注册、删除、重启或保存配置。
- 不允许 AGENT 自由执行 Telnet、SSH 或任意设备命令。
- 飞书卡片只作为查询和结果展示入口。
- 设备访问必须经过固定的只读接口和白名单。
- 日志、卡片和交接文档不得记录真实 OLT IP、community、账号、密码、Cookie、Token 或完整现场台账。

## 10. 推荐实现顺序

新会话开始开发时，按以下顺序推进：

1. 只读检查当前分支、未提交改动、现有 Feishu 查询边界和数据表结构。
2. 盘点现有数据是否同时具备：一级 ONU 关系、用户地址、村级可提取地址、ONU 实时状态和历史光功率。
3. 先设计村级归属标准化和“未归属/待确认”状态。
4. 设计事件、抽样对象、光功率基线和五天观察记录的数据模型。
5. 先实现本地只读查询和样例测试，不接入自动告警触发。
6. 再实现飞书卡片的汇总查询和明细查询。
7. 用脱敏固定样例验证恢复判定、趋势判定、数据不足和重复掉线场景。
8. 最后才进行现场只读验证；现场验证不得扩大到设备写操作。

## 11. 验收标准

功能完成不能只以卡片显示或 HTTP 成功作为验收。至少需要验证：

- 能按村级地址查询，且能区分已确认、推定和未归属数据。
- 能从村级结果反查一级 ONU、OLT、PON 口和抽样 ONU。
- 能正确区分仍离线、已上线但不稳定、稳定恢复和数据不足。
- 能建立抢修前光功率基线，并展示抢修后五天变化。
- 能发现相对基线持续变差、异常波动和反复掉线。
- 没有历史基线或采样不足时不会误报为正常。
- 飞书卡片展示的数量与本地只读查询结果一致。
- 不会触发任何设备配置、注册、删除、重启或保存操作。
- 日志和结果中不泄露敏感凭据、会话材料或完整现场数据。

## 12. 当前明确不做的事情

- 当前不编写功能代码。
- 不自动生成或执行熔接、ONU 配置或设备修复命令。
- 不把单个抽样 ONU 的正常状态解释为整个一级地址完全正常。
- 不在缺少可靠基线时硬编码统一 dBm 阈值。
- 不把一级 ONU 安装地址直接当成用户村级地址。
- 不在没有确认数据来源的情况下假设所有 ONU 都能自动获得村级归属。

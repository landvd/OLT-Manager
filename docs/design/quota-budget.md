# 定额预算设计

> 叫法：界面上表二定额统一叫“人工”，表四甲供材料统一叫“材料”；生成的预算书工作表名称保持模板原样。

决策见 [ADR-092](../decisions/ADR-092-quota-budget.md)。本文档记录实现细节和已核对过的计算样例。

## 1. 数据表（第 30 版迁移）

| 表 | 内容 |
| --- | --- |
| `quota_templates` | 导入的预算书模板：文件名、SHA-256、文件内容（base64，随数据库备份与还原）、基础信息单元格位置与默认值、导入时间、定额条数、是否当前使用 |
| `quota_items` | 模板“定额数据库”表：`template_id`、`code`、`name`（项目名称）、`detail`（项目明细）、`unit`、`price1`～`price4`（一至四类地区，读单元格计算值）、`work_content`、`sort` |
| `material_imports` | 单价表导入批次：文件名、SHA-256、导入时间、物料数、新增/改价/过期统计、是否当前使用 |
| `material_prices` | 物料：`import_id`、`code`（8 位物料编码）、`name`、`spec`、`attr`、`unit`、`max_price`、`min_price`、`contract_end`、`place`（出仓地方，仅常用物料表有）、`sheet`（来源分类表）、`common`（是否在常用物料表） |
| `budget_info_presets` | 基础信息模板：`name`、`fields_json`（基础信息表各行的值）、`is_default` |
| `budgets` | 预算：`name`（项目名称）、`location`、`info_json`（基础信息快照）、`template_id`、`material_import_id`、`created_at`（编制日期来源）、`created_by`（`desktop` 或飞书 open_id）、`updated_at` |
| `budget_quota_lines` | 表二行：`budget_id`、`seq`、`source`（`direct`/`pipe`）、`code`、`qty`、`reuse`（利旧）、`remark`、`utterance`（原话） |
| `budget_pipe_inputs` | 管道录入：`budget_id`、`trench_json`（各路面开挖长度）、`jacking_json`（孔数→长度）、`wells_json`、`subduct_json`、`soil_json` |
| `budget_material_lines` | 表四甲供行：`budget_id`、`seq`、`material_code`、`qty`、`price_snapshot`（加入时的最高价）、`remark`、`utterance` |
| `budget_name_history` | 最近填过的编制人/审核姓名，用于快捷选择 |
| `quota_learned_phrases` | 飞书定额模式学到的说法（第 31 版）：说法键、类型、编号、名称、原话例子、次数、是否纠正过 |

- 管道生成的表二行（`source = pipe`）每次由 `budget_pipe_inputs` 重新计算，不手工维护；同编号与直接录入的行在**输出时**合并数量。
- 物料价格在加入时快照；导入新单价表后，预算页提示“有 N 项单价已变化”，用户确认后才刷新。

## 2. 导入

### 2.1 预算书模板

1. 用户在 WPS/Excel 把 .xls 另存为 .xlsx，桌面“定额预算 → 模板”导入。
2. 校验：必须有“项目基础信息表”“工程费用预算表（表二）”“器材预算表（表四甲供）”“定额数据库”；表二能找到“人工费用降点数”，表四甲供能找到“甲供材料费用合计”；`workbook.xml` 的 `calcPr` 带 `fullPrecision="0"`（缺失时提示“以显示精度为准未开启，金额可能与手工表差几分”，但允许导入）。
3. 读“定额数据库”第 4 行起：B 编号、D 名称、E 明细、F 单位、G～J 单价、K 工作内容。
4. 首次导入时，用“项目基础信息表”D 列生成内置默认基础信息模板。

### 2.2 材料单价表

- 遍历除“目录”“常用物料”“光配件”外的工作表，找含“物料编码”的表头行，按列名识别：名称（材料/材料名称/物料名称）、规格（规格型号/物料规格）、属性、单位、合同最高价、合同最低价（含“最底价”写法）、合同期止、出仓地方。
- 只收 8 位数字编码的行；最高价为空时，取该行各供应商报价的最大值。
- “常用物料”表只用来标记 `common`、补合同期止和出仓地方。
- 找不到物料编码列或价格列的表跳过并在预览里列出；一张都识别不到时拒绝导入。
- 导入前预览：物料数、新增、改价、已过期（合同期止早于今天）、跳过的表；确认后整份替换为当前批次（旧批次保留以便回看）。

## 3. 计算

### 3.1 按显示精度取整

`displayRound(value, decimals)`：所有中间结果按目标格子的显示小数位取整后再参与下一步计算。

| 格子 | 小数位 |
| --- | --- |
| 表二 H、J、L、M | 2 |
| 表二 K | 千米 3 位，其余 2 位 |
| 表四 F | 4（公式本身带 ROUND） |
| 表四 H | 4 |
| 表四 J、K | 2 |

### 3.2 管道计算器移植

输入：`trench`（路面 → 长度，1 孔）、`jacking`（孔数 1～9 → 长度）、`wells`（类型、路面、个数）、`subduct`（直埋子管长度、路面）、`soil`（土质比例，默认普通土 0.5、砂砾土 0.5）。

| 定额 | 数量公式 |
| --- | --- |
| YGWG-1-01 施工测量 | 开挖长度合计 + 顶管长度合计 + 直埋子管长度 |
| YGWG-1-02～1-12 开挖路面 | 该路面长度 × 0.4 + 该路面上的井面积 + 该路面直埋子管 × 0.3 |
| YGWG-1-13～1-20 修复路面 | 该路面沟面积 + 直埋子管 × 0.3（井不修复；混凝土 250/350/450 都归 1-14） |
| YGWG-1-21～1-25 开挖土方 | (沟面积 × 0.85 + Σ井面积 × 井深 + 子管 × 0.3 × 0.4) × 土质比例 |
| YGWG-1-26 回填 | 沟面积 × 0.85 + 子管 × 0.3 × 0.4 |
| YGWG-1-27 倒运 | 开挖土方合计 − 回填 |
| YGWG-2-4 敷设塑料管道 1 孔 | 开挖长度合计 |
| YGWG-2-28 顶管 1 孔 | 顶管长度合计 |
| YGWG-2-29 顶管增加 1 孔 | Σ 长度 × (孔数 − 1) |
| YGWG-3-1 / 3-2 / 3-7 / 3-4 | 单页井 / 双页井 / 人手井 / 监控井个数 |
| YGWG-4-2 砂浆抹面 | 单页 3.28、双页 5.28、人手 3.02、监控 1.28 平方米/个 |
| YGWX-2-04 人工敷设塑料子管 | 直埋子管长度 ÷ 1000（千米） |

井面积/深度：单页 1×1.2、双页 1.3×1.6、人手 π(0.4)²（按 3.14）、监控 0.9×0.8；井深 0.85，监控井 0.6。数量为 0 的项不进表二。

### 3.3 已核对样例（作为单元测试）

1. 开挖混凝土路面 150mm 以下 20 米 → 施工测量 20、开挖 8、修复 8、普通土 3.4、砂砾土 3.4、回填 6.8、敷管 20；不含税 1454.76。
2. 开挖混凝土 250mm 以下 30 米、顶管 2 孔 15 米、单页井 2 个（混凝土 250 以下）→ 施工测量 45、开挖 14.4、修复 12、普通土/砂砾土各 6.12、回填 10.2、倒运 2.04、敷管 30、顶管 1 孔 15、增加 1 孔 15、手孔 2、抹面 6.56（与计算器一致）。
3. 顶管 3 孔 200 米 → 1 孔 200、增加 1 孔 400。
4. 表二：光缆端开缆 3 端、架空光缆敷设 36 芯以下 0.200 千米、光缆接续 48 芯以下 24 芯 → L 合计 1430.74、M 合计 1559.55；再加利旧架空 36 芯以下 0.200 千米（H 2235.16）→ 1877.77 / 2046.81（与现场表一致）。
5. 表四：GYTS-24B1# 24 芯光缆 800 米、PLC# 1 分 8 光分路器 6 个 → F 2.4635 / 16.7611，J 1970.80 / 100.57，合计 2071.37 / 2340.60（与现场表一致）。

### 3.4 监理费与 OA 提醒

- 监理费按模板表五第 9 行：计费基数（表一 F17）= 人工除税 ÷ (1 − 施工费下浮率) + 表三设备 + 材料（表四甲供）+ 表四乙供 ÷ (1 − 施工费下浮率)（本程序不录表三、表四乙供，按 0）；监理费（E9）= 基数 × 3.3% × (1 − 监理费下浮率)；含税（G9）= E9 × 1.06。各格按显示精度取 2 位（`computeSupervision`）。
- 安全生产费按模板表五第 10 行：建安费（表一 F15 = F16 − 表三，本程序与监理费计费基数相同）× 2%（E10），含税（G10）= E10 × 1.09（`computeSafety`）。
- 合计（含税）= 人工含税 + 材料含税 + 监理费含税 + 安全生产费含税。
- **人工含税 + 监理费含税 + 安全生产费含税 > 3000** 时提示“项目人工超过 3000，需要上 OA 系统”（`totals.needsOa`、`budgetView().oaNotice`）：桌面概况红色提示条，每次加入 / 修改后弹警告框；飞书清单卡片标题变红并加红字，连续添加卡片和“预算书已生成”卡片同样提示。

## 4. 解析

### 4.1 本地规则

- 数量：阿拉伯数字或中文数字 + 单位（米/千米/公里/个/端/芯/台/套/处/根…），单位与定额单位不同时换算（米 ↔ 千米 ↔ 百米）。
- 芯数：“24 芯”→ 在同名定额的“X芯以下/以上”档位中取不小于 24 的最小一档。
- 敷设方式：管道/架空/埋式/墙壁/吊线 → 对应定额名称前缀。
- 利旧：句中含“利旧”且定额名称含“光缆敷设”且不是皮线 → `reuse = true`。
- 管道：开挖（路面类型 + 厚度档 + 长度）、顶管（孔数 + 长度）、做井（类型 + 路面 + 个数）、直埋子管、土质比例。
- 材料：名称/规格关键词（芯数、1 分 N、型号片段）在物料库匹配；“常用物料”优先；括注用途写入备注。
- 指令：新建预算、打开预算、清单、改数量（“人工2改成5”）、删除（“删除材料1”）、上一步（撤销）、纠正（“是300米不是4千米”）、基础信息、改某项基础信息、生成预算书、退出定额模式。人工和材料各自编号；没说哪边时只有一边有第 N 项就用那边，两边都有就让用户说清楚。
- 一句话说几条：按逗号、分号、顿号、换行拆开；“人工：…材料：…”分段，段内各条带上所在分段；没有数字的小段（如“架空用”）并到前一段。
- 纠正：“是 X 不是 Y”“不是 Y 是 X”“改成 X”改数量；说了名称就在清单里找最像的那条，没说就改这次进入定额模式后最后录入的一条；单位按那条的单位换算。
- 提问和闲聊：不带数字、含“多少 / 哪些 / 清单 / 说一说”等的话给清单；其余不带数字的话只回简短提示，不问大模型、不给候选。
- 同义词：熔接 / 熔纤 = 接续，接续盒 = 接头盒，开端 / 开缆 = 端开缆；“架空光缆 300 米”“管道光缆”没说敷设也按人工（敷设）；“材料：48芯300米”只说芯数和长度按光缆。

### 4.2 学到的说法与大模型兜底

顺序：**学到的说法 → 本地规则 → 本地拿不准时问大模型**。

- **学到的说法**（`quota_learned_phrases`，第 31 版迁移）：飞书里每次“确认加入 / 改用这个”都记下“说法 → 定额 / 物料”，确认后直接生效。说法键是去掉数量、芯数、利旧、备注后的关键词（“做3个光缆头”→“做光缆头”），换数量、换芯数都算同一条；芯数、规格仍按规则定档。改选非推荐项时标记“纠正过”。桌面“模板与单价 → 学到的说法”可查看和删除。
- **本地拿得准**：定额首选得分 ≥ 0.85，且没有得分接近（相差 < 0.08）的不同名候选；材料首选得分 ≥ 0.9，且没有接近（相差 < 0.05）的不同名候选。同名多档（例如立水泥杆 6 米 / 7 米）不算拿不准，由用户在卡片上点选。
- **问大模型**：用大模型（与查询意图同一配置），只发原话、宽松筛出的候选池（定额最多 24 条，编号 Q1…；物料最多 16 条，编号 M1…）和最相关的 12 条已学说法；要求返回 `{"kind","id","quantity","unit","reuse","remark"}`。编号必须在候选池里，数量优先用本地解析的结果，芯数档按规则修正，价格一律由程序计算。超时 20 秒；失败、返回候选外编号或 unknown 时退回本地候选并在卡片上说明。
- 飞书里先发“正在理解”卡片，模型返回后替换成确认卡片；确认卡片上注明来源（按学过的说法 / 大模型理解）。

## 5. 飞书

- 进入：飞书开发者后台给机器人菜单加一项，事件 ID 填 `quota-mode`；或在单聊里说“定额模式”“做预算”。群聊里同样要 @机器人。
- 会话按人（群聊按群 + 人）记录当前预算，30 分钟无操作或说“退出”离开，回到普通查询。
- 指令：新建预算（表单：基础信息模板、项目名称、建设地点、编制人、审核）、打开预算、清单、人工 N 改成 M、删除材料 N、上一步、清空管道、基础信息、“地区类别改成三类”等改基础信息、生成预算书、帮助、退出。清单里人工、材料各自编号；管道生成的人工单独列出。
- **以表单为主（外勤不方便打字）**：清单卡片每行带“改”，底部是“＋人工 / ＋材料 / 管道”和“生成预算书 / 基础信息 / 退出”。新建预算、每次加入、修改后都回到清单卡片（替换原卡片）。
  - ＋人工：先出常用项按钮（同桌面的常用）和分类按钮；点常用项出这一项各档的表单，点分类出这一类全部档位的表单（常用在前，最多 100 项）。表单：选档位 / 项目、数量（千米的项目一律按米填，自动换算；写“0.3千米”也认）、利旧（是 / 否，只有光缆敷设能选）、备注。
  - ＋材料：直接出常用材料表单（单价表“常用物料”，按日常顺序），下面是其它分类按钮；分类表单最多列 100 项，常用在前。表单：选材料、数量、用途（架空用 / 管道用 / 直埋用 / 墙壁用 / 入户用）、备注（填了就不用用途）。
  - 改：人工可换同名另一档、改数量、利旧、备注；材料改数量、用途、备注；表单外有“删除这条”。
  - 管道：一张表单，开挖（路面 + 长度）、顶管（孔数 + 长度）、做井（类型 + 路面 + 个数）、直埋子管（长度），填哪项算哪项。
  - 连续添加：人工表单提交后回到选人工卡片（列出已录人工），接着选；“人工选好了，下一步选材料”转到常用材料表单；材料表单提交后留在同一张表单（列出已录材料），“材料选好了，看清单”回清单。修改、管道提交后回清单。
  - 基础信息卡片带“修改基础信息 / 返回清单 / ＋人工 / 主菜单”；修改表单列出除工程编号外的所有基础信息，默认值是预算现在的值，地区类别、勘察费按国标为下拉，费率按百分数填。表单字段较多，运行时表单值上限放宽到 40 个。
  - 主菜单：列出预算（点了打开），底部“退出定额模式”；清单、基础信息上的“主菜单”回主菜单，不退出定额模式。
  - 清单卡片第二行按钮：生成预算书 / 基础信息 / 主菜单 / 删除预算；删除先出确认卡片（“确认删除”或“取消，返回清单”），删除后回主菜单。
  - “预算书已生成”卡片：上 OA 提示是单独的红字一段（消息正文会转义 HTML），下面有“返回清单 / 主菜单”。
  - 填错（没选、没填数量、不能利旧）另发一条提示，原表单保留可以再提交；同一张表单只能提交一次。卡片控制在 30KB 内（分类按钮只放在常用材料表单上）。
- 说话为辅：每条录入回“请确认”卡片：推荐项和最多 3 个候选，点“确认加入 / 改用这个 / 取消”；卡片只有发起人能点。
- 一句话说了几条时回一张合并卡片，每条列推荐项：“全部加入”一次记入（“上一步”整批撤销）、“逐条确认”拆成单条卡片、“取消”。拿不准的条目先一起问大模型。
- “上一步”按这次进入定额模式后的录入顺序撤销（加的人工 / 材料删掉，管道恢复到加之前），最多记 20 步。
- 卡片一律 JSON 2.0（`src/feishu/quota-cards.cjs`）；`quota-*` 按钮在运行时一律按“先应答点击、再后台更新卡片”处理。定额模式直接注入 `quotaService`，不经过只读数据网关。
- 生成预算书：运行时调用 `im/v1/files` 上传（`file_type: xls`）后发文件消息，**飞书应用需要开通“上传、下载文件”（im:resource）权限**；发送失败时提示到桌面下载。文件名 `<项目名称>-预算书-<yyyyMMdd>.xlsx`。
- 谁能使用：沿用飞书机器人现有的授权用户，所有人都能用；每份预算记录创建人，桌面和飞书共用。

## 6. 桌面

- 没选预算时右边是概览（`GET /overview`）：预算份数、本月编制、飞书录入、最近要上 OA 的份数；最近 6 份预算的卡片（人工、材料、监理费、合计，超 3000 标“需上 OA”）；编预算三步和模板 / 单价表状态。打开预算后“返回概览”回到这里。
- 新页面“定额预算”：左边预算列表，右边一页平铺：概况（人工、材料、合计）、人工、材料；“基础信息”和“管道开挖 / 顶管 / 做井”点开后显示。
- 以点选为主：人工的常用项、材料的常用分类（光缆、光缆接头盒、光缆分纤箱、皮线光缆等，只列有常用物料的分表）各一行按钮；点人工常用项打开添加对话框并选好该项，光标停在数量框；点材料分类打开对话框并定位到这一类（常用在前）。“更多人工 / 更多材料”打开同一个对话框，按分类或搜索选择。
- 添加对话框：人工选档位（芯数档等）、填数量（千米的定额默认按米填，自动换算）、利旧开关（只有光缆敷设）、备注，下方显示单价和小计；材料填数量、点选用途（架空用、管道用、直埋用、墙壁用、入户用，或自己填）。“加入并继续”连续录入。
- 清单每行只有“改”“删”：“改”打开同一个对话框（可换档位、换材料、改利旧和备注），删除前确认。管道生成的行到管道计算器里改。
- 常用：人工默认光缆端开缆、架空光缆敷设、管道光缆敷设、光缆接续，材料取单价表“常用物料”，所有预算里用过 3 次的自动算常用；对话框里可以“设为常用 / 取消常用”（第 32 版迁移 `quota_common_overrides`）。
- “模板与单价”：导入预算书模板、导入单价表（预览后确认）、基础信息模板管理（新增/修改/删除/设默认/从当前预算另存）。

## 8. xlsx 改写器

1. CFB 以 zip 读入模板；按 `workbook.xml` + `workbook.xml.rels` 找到各工作表部件。
2. 定位数据区，计算需要插入的行数 `n`。
3. 对表二/表四甲供执行插行：把插入点及以下的 `<row r>`、`<c r>` 下移 `n`；新行复制模板首个数据行的行属性和单元格样式 `s`；更新 `<mergeCell>`（表二新行加 `E:F` 合并）、`<dimension>`、条件格式 `sqref`、数据有效性 `sqref`、共享公式 `ref`。
4. 遍历全部工作表的公式和 `definedNames`，把指向插入表、行号 ≥ 插入点的引用下移 `n`（含区域引用的端点，例如 `SUM(L6:L10)` → `SUM(L6:L10+n)`）。
5. 写入数据：字符串用内联字符串 `t="inlineStr"`，避免改动共享字符串表；公式写 `<f>`，同时写按 §3.1 算出的缓存值 `<v>`，让不重算的预览工具也显示正确金额。
6. 删除 `xl/calcChain.xml` 及其关系和内容类型登记；`calcPr` 保留 `fullPrecision="0"` 并加 `fullCalcOnLoad="1"`。
7. 其余部件不动，CFB 写回 zip。

测试：合成模板的插行引用调整单元测试；用用户提供的 WPS 另存模板做端到端测试：生成后 SheetJS 回读值与 §3.3 样例一致，WPS 打开无修复提示（人工确认）。

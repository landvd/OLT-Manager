# Pi Agent 终端助手与 Feishu 只读指令交接文档

> 交接对象：AGY
>
> 文档性质：需求、架构和安全边界交接
>
> 当前状态：仅完成可行性讨论，尚未编写任何 Pi Agent 功能代码

## 1. 背景

OLT Manager 当前支持多种厂商、型号和版本的 OLT。现场经常出现同一类查询命令因厂商、设备型号或软件版本不同而变化的情况，维护人员容易忘记或误用命令。

目标是在首页现有“打开终端”功能中增加可选的 Pi Agent 助手，使维护人员可以用自然语言询问：

- 当前 OLT 应使用什么查询方式。
- 某个槽位、板卡、PON 或 ONU 如何查询。
- 不同型号或版本的命令有什么区别。
- 某项查询结果代表什么。

同时，允许通过 Feishu 单聊发送受限的远程只读查询，由本机运行的 OLT Manager 访问现场 OLT，再将脱敏结果返回 Feishu。

## 2. 目标定位

Pi Agent 的定位是：

> 版本感知的 OLT 只读查询与命令解释助手。

它不是：

- 任意 Shell 或编程代理。
- 任意 Telnet/SSH 命令执行器。
- 远程配置下发机器人。
- ONU 自动注册、删除、重启或保存配置工具。

## 3. 推荐总体架构

```text
首页终端窗口 / Feishu 单聊
          ↓
现有 Feishu 权限、单聊和 OLT 范围校验
          ↓
Pi Agent：理解意图、选择工具、解释结果
          ↓
OLT Manager 受限只读工具层
          ↓
现有 SQLite、SNMP、固定 Telnet show、NMSE/OSS 只读适配器
          ↓
脱敏结果返回页面或 Feishu
```

推荐 Pi Agent 作为独立受限进程运行，通过 JSON-RPC 或等价的进程间通信与 OLT Manager 交互。不要让 Pi 直接控制 xterm、直接拥有系统 Shell 权限或直接管理设备凭据。

Pi 的 SDK 支持自定义工具和 JSON-RPC 子进程集成，可作为后续技术调研入口：

- https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/sdk.md
- https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/extensions.md

## 4. 首页终端集成方案

打开现有终端后，建议采用“终端 + 助手”并列布局：

```text
左侧：现有内置 Telnet 终端
右侧：Pi Agent 自然语言助手
```

Pi 助手可以继承当前页面上下文：

- 当前 OLT。
- 厂商和设备型号。
- 已知软件版本。
- 当前槽位、板卡、PON、ONU ID。
- 当前是否处于只读查询上下文。

但不得继承或读取：

- Telnet 密码。
- SNMP community。
- NMSE/OSS 密码、Cookie、token、CUID/FDN。
- 未脱敏的原始终端会话。

### 示例交互

用户问：“怎么查看 1/7/12 号 ONU 的光功率？”

- Agent 根据当前厂商、型号和版本匹配已验证的只读方式。
- 如果存在版本差异，展示适用范围和多个候选。
- 如果已有对应只读工具，优先直接调用工具返回结果。
- 只展示命令说明或查询结果，不自动输入终端。

用户问：“帮我注册这个 ONU。”

- Agent 拒绝执行。
- 可以解释人工操作所需的步骤或展示配置预览。
- 不得自动粘贴、执行或保存配置。

## 5. Feishu 远程指令方案

Feishu 只支持受限的自然语言只读查询，例如：

- 查询指定 OLT 的状态。
- 查询某个 ONU 的实时状态。
- 查询某个 PON 下的 ONU。
- 按姓名、地址或设备号查询候选。
- 查询本地历史光功率或已保存快照。
- 解释告警或查询结果。

推荐保留当前 Feishu 子系统作为传输、授权、范围和卡片交互层，Pi Agent 放在结构化意图之后，负责工具编排和结果解释。不要让 Pi 直接绕过现有 Feishu 合同读取原始消息并自行决定设备操作。

远程链路必须满足：

1. OLT Manager 主程序正在运行。
2. Feishu 子系统已由用户显式启用。
3. Feishu 长连接正常。
4. 本机能访问目标 OLT。
5. 查询目标属于当前已启用 OLT 范围。
6. 结果经过字段投影和敏感信息脱敏。

Feishu 不得：

- 远程打开本地终端。
- 向终端注入输入。
- 发送任意 Telnet/SSH 命令。
- 触发配置、注册、删除、重启或保存。
- 返回数据库、管理 IP、凭据或原始上游响应。

## 6. 版本差异处理

Agent 不应依赖自由生成命令解决版本差异，而应使用“厂商/型号/版本/命令”知识库或命令目录。

每条命令至少记录：

- 厂商。
- 设备型号。
- 软件版本范围。
- 命令用途。
- 只读/配置/保存分类。
- 是否允许 Agent 调用。
- 是否已通过样例或现场验证。
- 失败时的替代命令或下一步确认方式。

Agent 对问题应有三种结果：

### 已验证

明确说明适用当前型号/版本，并可调用对应只读工具。

### 存在差异

列出不同版本的候选方式，说明各自适用条件，不自动试错。

### 无法确认

不猜测命令，先建议读取版本信息或要求用户确认设备版本；未知命令只能作为人工参考，不能自动发送。

## 7. Agent 工具边界

初期只开放领域工具，不开放 Pi 默认的通用 Shell/文件工具。

建议工具范围：

- 读取 OLT 基本状态和 SNMP 可达性。
- 查询已注册 ONU。
- 查询未注册 ONU/ONT。
- 查询 ONU 详情、状态、光功率和距离。
- 查询 PON 台账。
- 查询本地历史快照。
- 查询已保存的 NMSE/OSS 只读数据。
- 生成配置方案文本预览。

明确禁止：

- `bash`、任意文件读写、任意代码执行。
- `snmpset`。
- 任意 Telnet/SSH 命令。
- ONU 注册、授权、删除、重启、恢复出厂。
- 自动粘贴、自动执行、保存配置。
- 任意 URL、任意 DWR 或任意远端接口代理。

所有工具调用必须经过参数校验、OLT 范围校验、字段投影、超时、取消和输出截断。

## 8. 结果与安全要求

Agent 返回结果时应区分：

- 当前实时设备结果。
- 本地保存快照。
- 历史数据。
- 仅为命令建议。
- 未验证或不确定结果。

不能仅因 HTTP 200、工具调用成功或模型给出命令，就判定设备查询成功。应以实际结构化数据、设备返回内容和明确的来源状态为准。

长结果必须分页、摘要或截断，避免把整台 OLT、完整用户资料或原始终端输出送入模型上下文。

Agent、日志、审计、Feishu 回复和错误消息不得包含：

- 密码。
- SNMP community。
- Cookie、token、会话材料。
- 完整管理地址清单。
- 未脱敏的用户电话、地址或完整现场台账。
- 原始 NMSE/OSS 响应。

## 9. 兼容性与运行模式

当前项目使用 Electron 22，并保留 Windows 7 x64 发行边界。因此需要把 Pi 运行时兼容性和主程序兼容性分开验证。

建议：

- macOS：可选使用本地模型或远程模型。
- Windows 7：优先考虑远程模型 API；若 Pi 运行时无法稳定支持 Win7，则关闭 Agent，不影响终端和普通 OLT 查询。
- Pi 不可用、模型不可用、网络不可用时，终端功能和现有 Feishu/OLT 只读功能继续运行。
- 默认保持单个 Agent 请求，设置上下文、输出大小和超时上限，避免本地模型引发内存压力。

## 10. 建议实施顺序

本交接文档不授权立即实现以下全部内容，建议 AGY 按阶段实施：

1. 只读设计盘点：确认现有终端、Feishu、CLI 工具和 OltDataGateway 的接缝。
2. 本地终端助手：只支持自然语言解释和只读查询。
3. 版本感知命令目录：加入型号、版本、验证状态和替代命令。
4. Feishu 接入：复用现有结构化 intent、单聊和 OLT 范围校验。
5. 独立 Pi 进程、超时、取消、崩溃隔离和模型配置。
6. macOS 与 Windows 7 桌面包分别验证，不因 Agent 失败阻断主程序。

## 11. 验收标准

### 功能验收

- 首页终端窗口可以打开 Pi 助手。
- 用户可以用自然语言询问 OLT 命令和查询结果。
- Agent 能识别当前 OLT 厂商、型号和版本上下文。
- 对已验证命令给出正确适用范围。
- 对版本差异给出多个候选或明确要求确认。
- Agent 可以调用现有只读工具返回结构化结果。
- Feishu 单聊可以发起同一套受限只读查询。

### 安全验收

- Agent 没有任意 Shell、文件写入或任意设备命令能力。
- 不能自动向 xterm 粘贴或执行文本。
- 不能执行 SNMP 写入、配置保存、ONU 注册/删除/重启。
- Feishu 不能绕过 OLT 启用范围和单聊限制。
- 凭据、Cookie、token、community 和原始响应不进入 Agent 上下文或输出。
- Pi、模型或 Feishu 故障不影响现有终端和本地只读页面。

### 证据要求

- 单元测试验证意图、工具白名单、版本匹配和拒绝路径。
- 使用合成数据验证敏感字段脱敏和输出截断。
- 使用脱敏设备样例验证不同厂商/版本的命令选择。
- 单独验证 macOS 桌面包和 Windows 7 x64 包的启动、终端和 Agent 降级行为。
- 真实设备验证必须明确区分“只读查询已验证”和“配置行为未执行”。

## 12. AGY 开始前必须确认

- 不修改现有只读设备边界。
- 不把 Pi 默认 Shell/文件工具直接暴露给模型。
- 不让 Agent 直接控制终端输入。
- 不用自由生成的命令替代版本化命令目录。
- 不将 Feishu 原始消息直接转换成任意设备命令。
- 不把模型输出、HTTP 200 或工具调用成功当作设备业务成功。
- 每个阶段保持小范围、可回滚、可单独验收。

# Huawei 配置命令与 ONT ID 修复

## 目标

修复内置 Telnet 的登录与“粘贴剪贴板”链路，并修正 Huawei ONT ID 与 service-port 不一致：保留生成器原文，避免 Huawei OLT 在整段高速输入时丢失空格、换行或末尾回车；不改变 OLT 只读边界。

- [x] 读取项目约束并确认现象与代码路径
- [x] 设计并实现最小粘贴传输修复
- [x] 增加回归测试并运行相关测试
- [x] 构建桌面目录包并核对运行产物
- [x] 修正 Huawei 候选 ONT ID 计算和实际 ONT ID 传入逻辑
- [x] 增加空位扫描与 API/模板回归测试
- [x] 重新构建并启动最新桌面包
- [x] 修正 Huawei 自动发现未注册列表的自动发现 OID、状态过滤与已注册 SN 去重
- [x] 运行回归测试、构建并现场只读刷新确认
- [x] 修正 Win7 Huawei 数据查询的负数接口索引并重新打包
- [x] 修正 Win7 Huawei ONU 光功率的 16 位有符号值解码并重新打包

## 成功标准

- 剪贴板内容不被改写。
- 内置终端发送时按命令行保留空格，并使用明确的 Telnet 回车。
- Huawei 方案最后一条命令不需要人工二次回车。
- 现有生成器测试、终端测试和构建通过。
- Huawei 先扫描同 PON 的空闲 ONT ID，优先使用第一个空位，没有空位才使用最大 ID + 1；native-vlan 与 service-port 共用该 ID。
- Huawei 未注册列表使用 MA5800 自动发现表 `...48.1.2`，并排除已注册 ONT SN；注册结果 `...52.1.3` 仅作辅助校验，避免历史注册表记录混入。
- Win7 Huawei 数据查询遇到负数接口索引时，需还原为无符号 32 位 OID 子标识，不能把负数传入 SNMP OID 编码器。

## 约束

- 不连接或写入真实 OLT。
- 不输出或保存任何现场凭据。
- 保留工作区已有用户改动和未跟踪规划目录。

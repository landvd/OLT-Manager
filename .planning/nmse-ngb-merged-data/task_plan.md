# NMSE-PON 与网管二期统一数据实施计划

## 目标

在 `codex/nmse-ngb-merged-data` 分支中，将网管二期作为 ONU 主数据源，使用 NMSE-PON 的 LOID 与完整姓名补充本地统一 SQLite 数据，并扩展飞书卡片的 LOID 回显与历史光功率能力。

## 阶段

- [completed] 1. 分支、现状和安全边界确认
- [completed] 2. 网管二期 ONU 全量只读适配器
- [completed] 3. 合并表、冲突表和同步前备份
- [completed] 4. 合并 API、页面和定时同步
- [completed] 5. ONU 查询与 Feishu Gateway 接入
- [completed] 6. Feishu LOID 回显与历史光功率卡片
- [completed] 7. 测试、文档、构建和运行验收
- [completed] 8. 拆分网管二期/NMSE-PON独立同步与手动合并
- [completed] 9. 独立同步 UI、API、数据库恢复和回归验收
- [completed] 10. 合并字段回退、现场经验和继续开发文档

## 固定决策

- 最终坐标以网管二期槽/板卡/PON/ONU ID 为准。
- 先获取网管二期，再获取 NMSE-PON，再事务合并。
- 跨坐标迁移优先使用唯一 LOID；LOID 缺失时只允许严格坐标回退。
- 冲突保留网管二期行、姓名留空并记录冲突，不猜测。
- 每次合并前生成并校验完整 SQLite 备份。
- Feishu 不在查询时触发远端同步。
- 飞书“复制 LOID”采用回显 LOID 文本供用户复制；历史光功率默认查询最近 7 天。
- 网管二期与 NMSE-PON 分别保存源快照；手动合并只读取本地源快照，不重复访问远端。
- 独立同步失败不覆盖对应源快照；手动合并失败不覆盖上一版最终合并数据。
- NMSE 联系人字段非空时优先采用 NMSE；NMSE 无匹配或字段为空时保留网管二期联系人，避免最终快照空白。
- 现场字段映射必须以脱敏实测字段为准；新增映射只影响下一次源同步，不自动修复已丢失的历史快照字段。

## 验收门槛

- 真实网管二期响应只通过固定只读适配器和字段投影进入本地。
- 失败同步不覆盖上一次成功合并数据。
- 示例旧坐标与新坐标通过 LOID 正确迁移完整姓名。
- 不写入 OLT、NMSE-PON 或网管二期远端配置。
- 全量测试、构建、语法检查和 `git diff --check` 通过。
- 独立 API 专项覆盖两套源分别成功、手动合并不触发远端读取、旧全量入口和失败保留旧数据。
- Codex 内置浏览器确认资源管理页显示四个同步入口，未登录时按对应权限禁用。
